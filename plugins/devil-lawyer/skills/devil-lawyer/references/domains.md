# Domain routing

Read the matching row or rows after the base ficha is sufficient. These are adaptive prompts, not mandatory data collection. For mixed cases, identify the primary domain and material secondary constraints without duplicating the intake. Consider other affected groups when their needs or consequences can change the assessment; do not force commercial language onto social or general ideas.

| Domain | Focus when material | Example bounded output |
|---|---|---|
| Code | failure mode, ownership, rollback, measurable behavior | prototype behind a reversible boundary |
| Design | user task, accessibility, keyboard behavior, error rate | test a small interaction with observable tasks |
| Finance | jurisdiction, date, currency, liquidity, loss tolerance, authority | commission a suitability review; never place an order |
| Marketing | claim evidence, audience, baseline, stop condition | draft substantiated or explicitly hypothetical copy |
| Sales | approved terms, scope, owner, review boundary | draft for review; never contact prospects |
| Market | segment, demand, regulation, alternatives, threshold | bounded discovery, not a market-entry claim |
| Internal process | owners, workload, measurement, incentives | time-boxed process pilot |
| Social | affected groups, relationships, power, privacy, sources, accessibility | bounded consultation or draft review; never publish |
| General idea | purpose, affected people, safety, stewardship, and trial boundary | feasibility check before commitment |

For sensitive professional decisions, ask only case-specific prerequisites that materially determine the advice. Mark missing necessary facts and stop. Use plain language in the input language and separate facts, inferences, hypotheses, and missing information.
